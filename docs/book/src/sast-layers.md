# 工程借鉴:从 codegraph 到企业级静态分析的分层架构

很多团队的讨论最终都会走到同一个问题:**"我们已经有 tree-sitter 的符号索引了,能不能直接往上做静态分析(SAST)?"** 或者反过来:"SAST 引擎是不是天生就不该走 tree-sitter 这条路?" 两个问法都预设了二选一,而正确的答案是**分层**——tree-sitter 和编译器前端各自待在适合的层上。本章把 CodeGraph 作为一块积木放进这个分层图景里。这是一章"读后借用",不假设你要直接用 CodeGraph 做安全产品。

## 五层架构

```
L4  AI 研判层      降噪 · 修复建议 · 报告解释        ← 概率模型,可替换
─────────────────────────────────────────────────
L3  规则引擎       污点分析 / 漏洞规则 → 候选告警    ← 确定性,可审计
L2  图索引层       符号 · 调用图 · 可达性            ← 确定性的共享底座
L1  代码理解       clang AST(预处理后真实代码)      ← 编译器事实
L0  构建捕获       真实编译命令 → 编译数据库         ← 地基
```

各层的职责,用一句话说清:

- **L0 构建捕获**:在客户真实编译过程中抓取编译命令,产出编译数据库(`compile_commands.json`)。没有它,C/C++ 后面的一切都建立在猜测上。
- **L1 代码理解**:编译器前端(clang)看到的是**预处理之后**的代码——宏展开、条件编译选中分支、真实类型。
- **L2 图索引**:把符号和关系物化成可查询的图,供 L3 的规则和 L4 的研判共同消费。**CodeGraph 就活在这一层。**
- **L3 规则引擎**:明文规则在图上找"危险长什么样",产出候选告警,不下最终结论。
- **L4 AI 研判**:对候选做"值不值得人看"的裁决,附上可复核的推理链和修复建议。

## 为什么这么分:按可信度切,不按功能切

分层的根本理由是**各层答案的可信度不同,而错误的爆炸半径向下递增**:

| 层 | 产出性质 | 它错了会怎样 |
|---|---|---|
| L1/L2 | 事实,可复现 | 全链崩——底账错一条边,上面全错 |
| L3 | 机器判断,死板但稳定 | 误报,改规则重跑即可 |
| L4 | 智能判断,聪明但会错 | 单个告警误判,吞掉重来 |

所以有一条铁律:**不可信的层只许消费可信的层,不许反向污染**。L4 只能对 L3 挑出的候选做确认/否决/解释,不能凭空"发现新漏洞"——因为它的判断不可复现,而 L3 的候选可以重放审计。

分层同时解决了三个工程问题:**贵的计算只沉淀一次**(编译几十分钟,规则重跑分钟级,模型替换秒级);**各层变化节奏解耦**(工具链、代码、规则、模型各自升级互不重测);**一个产品同时卖确定性和智能**(CI 门禁要"同一份代码同一结果",降噪要模型——只有分层能同时满足)。

## tree-sitter 与编译器前端:分工,不是替代

本书的 macro 章节已经给了实证:tree-sitter 看到的是未预处理的源文件,宏对它是黑盒。所以分工应当这样划:

**tree-sitter 适合**:符号索引、函数/变量切片、跨语言导航、agent 检索——它的统一 AST 接口覆盖几十门语言,边际成本极低,而且"静默优于错边"的策略在这些场景里是正确的精度护栏。

**编译器前端必须接管**:C/C++ 的精度分析。宏、条件编译、跨编译单元的符号可见性——这些不是工程问题,是结构性天花板。需要完整、可审计调用图的地方(污点分析的底图、审计证据链),tree-sitter 给不出来。业界的商用静态分析产品(Coverity、CodeQL 等)都要求编译或编译数据库,原因就在于此。

**误判来自把两层混为一谈**:用 tree-sitter 做审计级 C/C++ 分析会撞 macro 墙;反过来用 clang 为所有语言建索引,既丢掉了多语言覆盖,也背上"必须先编译成功"的部署成本。

## 嫁接路径:CodeGraph 的替换点在哪

如果要为已有构建捕获能力的团队复用 CodeGraph,改造点很清晰:**它的提取层是可替换的**。所有语言 extractor 产出统一的 `ExtractionResult`(节点/边/未解析引用),写进同一个 SQLite 图库,下游的解析、合成、查询一概不关心这些事实来自 tree-sitter 还是 clang。

所以合理的形态是**混合提取**:

- C/C++ 的 extractor 由 clang 编译事实驱动(宏展开后真实代码);
- 其余语言继续走 tree-sitter;
- 边上的 `provenance` 扩展为分级信任:编译器事实 > tree-sitter 事实 > 启发式合成 > agent 推断——本书反复强调的"出身标签"机制,在这里成为混合事实源的信任协议。

需要一并记住的两件事:其一,**换掉解析器不解决内存问题**——超大仓库的工程调优是独立课题(见定位章的边界二);其二,**图变准了也只是骨架**——污点分析和漏洞规则是 L3 的新增工作,不会从嫁接里自动长出来。

## AI 研判层的设计原则(全部来自本书已验证的机制)

CodeGraph 没有 AI 研判层,但它为 agent 设计工具的那套原则,恰好是 L4 的工具接口规范:

1. **精确进、精确出。** 工具参数是符号名/告警 ID,不是自然语言描述。本仓砍掉 `codegraph_context` 的教训:模糊输入的工具只能在黑箱里猜用户意图,猜错就返回错误功能的代码,而且无法复核。消歧要发生在工具调用之间(先列候选再选),不是调用内部。
2. **成功形状的响应。** 一两次 `isError` 会教会 agent 永久弃用你的工具。"未索引""未找到"这类预期内状态必须返回带指引的成功响应;isError 只留给真正的故障和安全拒绝。
3. **五问清单。** 一条候选告警的标准审讯:源可信吗(攻击者能否控制输入)、路走得通吗(路径上的分支门控)、校验真没有吗(项目自定义的净化函数)、代码活着吗(在这个客户的构建配置里生效吗)、值多少钱(可利用性)。前四问的答案都应来自对图的确定性查询;模型贡献的是"问什么"和"把事实拼成结论"——空口数据不可信这类世界知识。
4. **判决必须带可回放的事实链。** 每个结论附工具调用记录,人不同意时可以逐环复查。同时保留"存疑上交人"的第三桶,不许强判二元结论。
5. **桥接一半的路径比没有还糟。** 本仓的实测铁律:给了半截攻击路径,agent 会以为"查过了"而更执着地去读源码补另一半,Read 次数反而上升。研判工具要么给出端到端的路径,要么诚实声明图在哪断了。

## 收束

把这本书压缩进这个分层图景:**CodeGraph 交付的是 L2——一张确定性、带出身标签、可被多方消费的图**。它不交付 L3 的规则,也不交付 L4 的研判。如果你的目标是 agent 编码辅助,直接使用即可;如果你的目标是静态分析产品,它适合的用法是那块"不会说谎的底座"——上面的规则与智能,建立在这个底座够硬的前提上。
